# House Value Estimator

A FastAPI service that predicts house prices using a trained Random Forest regression model. The project demonstrates layered backend architecture, request validation, logging, database persistence, automated testing, Docker containerization, GitHub Actions CI, Git LFS, and deployment on Render.

🔗 **Live API:** https://value-estimator.onrender.com/

📚 **Swagger UI:** https://value-estimator.onrender.com/docs

---

## Overview

The project separates machine learning inference from API routing, business logic, and database access through a layered backend architecture.

Key characteristics include:

- Clean layered architecture (Route → Service → ML Predictor / Repository)
- Centralized configuration and logging
- Request validation and error handling
- Persisted prediction history in a database
- API key authentication and rate limiting
- Automated test suite with CI on every push
- Containerized with Docker and deployed to Render using Git LFS for the model file

---

## Features

- **POST `/predict`** — get a price prediction from house features
- **GET `/predictions`** — paginated prediction history
- **GET `/health`** — health check endpoint
- **GET `/docs`** — interactive Swagger UI (auto-generated by FastAPI)
- API key authentication on protected routes
- Rate limiting (20 requests/minute/IP) on the prediction endpoint
- Prediction history persisted in SQLite via SQLAlchemy

## Architecture

**Prediction flow:**
```
POST /predict
      ↓
Prediction Route
      ↓
Prediction Service
      ↓
ML Predictor
      ↓
Prediction Result
      ↓
SQLAlchemy ORM
      ↓
SQLite Database
```

**History retrieval:**
```
GET /predictions
      ↓
Prediction Route → Prediction Service → Repository → SQLAlchemy → SQLite
```

**Project structure:**
```
value_estimator/
├── backend/
│   ├── app/
│   │   ├── main.py                       # FastAPI app entrypoint
│   │   ├── core/                         # Config, rate limiter
```

## Getting Started

### Prerequisites
- Python 3.11+
- Git LFS (`git lfs install`) — required to pull the ML model file
- Docker (optional, for containerized runs)

### 1. Clone the repo

```bash
git clone https://github.com/Arpitaraskar/value_estimator.git
cd value_estimator
git lfs pull
```

### 2. Set up a virtual environment

```bash
cd backend
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Configure environment variables

Create a `.env` file inside `backend/`:

```env
API_KEY=your-api-key-here
```

### 4. Run the app

```bash
cd backend
uvicorn app.main:app --reload
```

Visit:
- API root → `http://localhost:8000/`
- Swagger docs → `http://localhost:8000/docs`

---

## Running with Docker

```bash
cd backend
docker build -t value-estimator .
docker run -p 8000:8000 --env-file .env value-estimator
```

The trained model is tracked using Git LFS and is included in the Docker build so the production container can load it.

## API Usage

### Predict a house price

```bash
curl -X POST "http://localhost:8000/predict" \
  -H "Content-Type: application/json" \
  -H "x-api-key: your-api-key-here" \
  -d '{ ... house features as defined in app/schemas/house_schema.py ... }'
```

The exact request fields are defined by the `HouseFeatures` schema and are documented in the interactive Swagger UI at `/docs`.

### Get prediction history (paginated)

```bash
curl "http://localhost:8000/predictions?skip=0&limit=10" \
  -H "x-api-key: your-api-key-here"
```

**Validation rules:**
- `skip >= 0`
- `1 <= limit <= 100`

## Running Tests

```bash
pytest
```

With coverage:

```bash
pytest --cov=app
```

The suite includes:
- Unit tests for routes, services, and the predictor (mocked)
- Integration tests (model loading mocked out)
- Rate limit test (verifies HTTP 429 after the limit is exceeded)
- Pagination and validation tests
- Auth tests (missing/invalid API key → 401)

Tests run against an isolated in-memory SQLite database — the real `data/prediction.db` is never touched.

---

## CI

GitHub Actions runs the full test suite automatically on every push:
- Sets up Python 3.11
- Installs dependencies
- Runs `pytest`
- Uses mocked model loading so CI doesn't need the real `.joblib` file

---

## Deployment

Deployed on **Render** using Docker.

Key points:
- The trained ML model (~145 MB) is tracked using **Git LFS** because it exceeds GitHub's standard 100 MB file size limit.
- The Docker `CMD` uses Render's dynamic port:
  ```dockerfile
  CMD ["sh", "-c", "uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}"]
  ```
- Secrets (API key) are supplied via environment variables at runtime — never baked into the image.
